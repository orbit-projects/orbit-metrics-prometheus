## Lifecycle, failure behavior, and limits

`orbit-metrics-prometheus` adapts Orbit metric snapshots to the Prometheus text exposition format. It also
provides an optional Core plugin that contributes `/metrics`; Core itself does not reserve or serve
that route.

```bash
pip install orbit-core orbit-security orbit-metrics orbit-metrics-prometheus
```

```python
from orbit import Application, ApplicationConfig
from orbit_metrics_prometheus import PrometheusPlugin

app = Application(ApplicationConfig(name="example"))
app.register_plugin(PrometheusPlugin())
```

The endpoint requires the `orbit.metrics.read` role by default. Grant it to the configured scrape
identity through an `orbit-security` `RoleAuthorizer` supplied to `ASGIApplication` alongside an
authenticator. Core stores the route requirement but does not evaluate it. You can explicitly use
`PrometheusPlugin(roles=frozenset())` only when a separate network boundary makes public access
appropriate. Do not expose operational metrics unintentionally.

The exporter rejects metric-family/sample-name collisions (including names generated by histogram
families) and caps each exposition response at 8 MiB to bound scrape-time memory use. Reduce metric
label cardinality or split instrumentation across registries if an application reaches this limit.

## Production validation

Validate startup/shutdown cleanup, timeout and cancellation behavior, concurrency and payload bounds where applicable, secret rotation and least-privilege access, data durability, backup/restore, and failover against the selected provider. Do not infer distributed or durable guarantees from an in-process API or fake-client tests.
